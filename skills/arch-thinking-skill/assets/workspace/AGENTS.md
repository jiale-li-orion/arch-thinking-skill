# 工程工作区接续

本文件保存稳定读取规则与当前接管入口。项目已有规则持续生效，整合时保留原文。通用方法与六条工程判断规则见 [工程思维](工程思维.md)，日常实施持续遵守。

## 当前接管入口（随任务维护）

初始化时结合真实材料填写：当前任务及其 [STATE](STATE.md) 位置、对应设计来源、优先读取的模块或链路、实际执行入口。任务事实在 STATE 或原任务系统维护，本段负责定位。

## 读取与行动

- 接管或上下文压缩后，读 README 定位实际资产，全文恢复简洁的 ARCHITECTURE 和 STATE，并重读工程思维中的六条判断规则。复杂模块按当前任务展开；简单自包含编辑加载相关背景。
- 首次接入全文读取工程思维；选择复用或修复边界、调查跨模块故障、修订系统理解时回读相关章节。工程思维中的六条判断规则持续生效。
- 实施前恢复已批准设计、验收和当前实现差距；设计可以来自 chat。已有设计直接引用，会话独有且影响接续的关键内容保存到 STATE。
- 按任务选择实施、Debug、重构或交付策略；多套实现和历史兼容影响当前任务时，先定位真实生效路径。
- 用 rg / rg --files 定位入口、读写者、选择条件与消费者。全局关系指导局部搜索，局部事实修正对应架构解释。
- 执行与发布沿当地配置、runbook、工作树和授权继续，现有任务、进程及用户改动按实际状态承接。

## 更新责任

全局边界、依赖、状态所有者或共同约束改变时更新 ARCHITECTURE；具体生命周期改变时更新相关模块或链路；任务契约、差距、选择和交付状态改变时更新 STATE。对应图和引用随实际关系同步。

规则与状态分段维护。用户规则、设计原文及确定的约束按来源保留，规则修订依据明确授权。当前正文原位更新，历史由 Git、任务与已有决策记录承接。重要判断附源码、配置或运行依据。

整理长期架构知识时，以编辑开始时的正文和源码版本为基线。每项删并标明原位置、依据、保留位置及从保留知识恢复原判断的路径；再给一个相关的新消费者、失败恢复或旧数据情形，核对不同解释怎样更新。需要重新调查才能恢复的机制区别继续保留。更新正式正文后，沿受影响的调用、数据与部署依赖修订图和入口；已有项目规则逐字核对。

图保留对系统和局部行为的解释，代码细节按需追踪。合并知识时保留会影响后续修改、重试、恢复或兼容判断的条件。后台操作的句柄与接续路径保存到实际任务记录，STATE 提供入口。
