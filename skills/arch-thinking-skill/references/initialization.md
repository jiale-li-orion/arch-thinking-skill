# 建立可接续的工程工作区

用户要求 init，或长期维护、跨模块工作缺少可接续的系统知识时使用。一次性局部任务依据现有项目资料与源码推进，按复用价值决定文档沉淀。结构建立与知识恢复分别完成；Agent 负责把模板变成真实正文。

初始化同时包含全系统梳理或 PRD／技术设计重建时，加载[系统重建](system-reconstruction.md)。下文的一条相关行为用于启动模型，交付按该任务的模块覆盖与解释深度继续完成。

## 先接入已有资产

读取项目 README、适用 AGENTS、用户设计、现有架构、任务和运行入口，确认源码根与知识位置。沿用已有同职责文档的位置，通过 README 绑定路径；内容按来源、版本与源码依据核对，用户确定的契约持续继承。只有缺少的职责需要补齐。小型局部任务按实际接续需要补文档。

默认使用源码工作区内的普通文件。已有 `docs/`、`.arch/` 或其他知识位置可用 `--memory-root` 指定；沿用已有独立知识目录时继续核对源码版本。工作区文件与 Git 承担长期记忆。

## 补齐结构

脚本路径相对于 Skill 根目录：

```bash
python3 scripts/arch_memory.py init --root /path/to/repo
python3 scripts/arch_memory.py init --root /path/to/repo --memory-root /path/to/repo/docs/architecture
```

默认在源码根补 README、AGENTS、工程思维、ARCHITECTURE、STATE；已有旧版 `.arch/` 且根目录缺少 ARCHITECTURE 时自动接续旧位置。已有文件保留原内容。脚本只补缺文件，Agent 随后按职责整合现有索引和指令。自定义命名体系优先定点补内容。

## 从真实材料恢复知识

1. **恢复任务契约。** 使用 chat、设计文档、issue 和反馈，明确预期行为、确定的决策、验收、当前授权及实施自由度。会话独有的关键契约保存于 STATE，已有正式设计保留引用。
2. **建立初始架构。** 从构建入口、运行进程、主要模块、配置和存储恢复系统职责。按[知识维护的制图方法](knowledge-maintenance.md#图是模型的一部分)画实际系统图，并将当前任务涉及的模块与关键接口展开。记录代码或配置入口、当前版本、依据类型、覆盖范围及仍需核对的关系。
3. **追一条相关行为。** 连接用户入口、实现选择、生产消费、状态写入与最终结果。已有项目依据代码解释现状；新项目把目标设计和当前实现分别标明，随实施更新。
4. **形成当前状态。** 写清当前任务阶段、已完成部分、实现差距或故障机制、修改边界、下一动作及验证方式。现有进程、PR 和部署状态按实际记录接续。
5. **绑定阅读和维护。** README 指向真实资产；AGENTS 保留当地规则并补接管入口；工程思维承接通用方法和六条工程判断规则。模块与链路细节按需分离，保持全局正文简洁。

## 接续就绪

从项目入口重新恢复：任务要求什么；系统怎样完成相关行为；设计、代码与运行状态各是什么；当前应改哪里及影响什么；下一步怎样取得有效证据；详细依据位于何处。由这些内容直接开始当前工作。

模板提示仍在时，继续完成相应知识恢复。材料缺口按影响记录；涉及关键产品决策的缺口向用户澄清，独立且已授权的工作继续执行。文档结构存在和工程接续就绪分别说明。
