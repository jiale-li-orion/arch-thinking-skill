# 维护工作区理解与接续能力

系统认知、任务状态、文档职责或代码关系发生变化时使用。工作区拥有知识，Skill 提供读写方法；普通文件和 Git 保存现行解释与历史。

## 职责与按需读取

| 职责 | 默认位置 | 读取或更新触发 |
| --- | --- | --- |
| 入口、实际路径和导航 | README | 接管；资产位置或职责改变 |
| 稳定规则与接管入口 | AGENTS | 接管；按权限修改规则或入口 |
| 通用工程判断方法 | 工程思维 | 首次使用；复用、修复边界或理解发生偏差 |
| 全局系统模型及架构图 | ARCHITECTURE | 恢复简洁全局；边界、依赖或状态归属改变 |
| 当前契约、进展、差距及接续 | STATE | 接管；任务判断、执行或交付状态改变 |
| 模块和关键生命周期 | 现有模块文档、flows | 相关实现、故障、复杂状态或兼容关系 |
| 具体执行、评审和运维事实 | 现有任务、PR、runbook | 对应执行或交付；详细产物留在实际位置 |

文件名由项目入口绑定，复用已有职责。项目 AGENTS 的固定规则与动态入口分段维护；动态入口指向 STATE 和实际任务，正式事实各自保存。

## 图是模型的一部分

图帮助人类理解真实现状并选择修改方案。先明确图要支持的判断，再选择视图；沿业务对象和关键边逐层进入证据。

| 视图 | 人类应能回答 | 需要显式保留的关系 |
| --- | --- | --- |
| 系统架构图 | 用户行为经过哪些运行单元，事实存在哪里，部署条件怎样选择路径 | 主要入口、进程或服务、外部依赖、权威存储及副本、同步与异步交接 |
| 模块架构图 | 哪个责任由谁承担，公共修改影响谁，哪些差异有独立归属 | 职责、接口、状态所有者、真实调用方与消费者、多套实现的选择条件 |
| 行为时序或状态图 | 一个对象怎样得到当前结果，在哪一步偏离，恢复怎样发生 | 对象与尝试身份、状态版本、读写、条件分支、提交与确认、重试取消及必要的并发顺序 |
| 语义依赖图或图旁关系说明 | 某个保证依赖什么，改变前提后哪些行为需重看 | 保证、建立与维持它的责任、使用它的行为、条件有效期及共享前提 |

保持简洁系统图，当前任务涉及的模块和链路按需展开。语义依赖可写在模块图的边和相邻正文中；一个清楚的视图足以支持决策时沿用它。目录和导入关系用于找代码，运行选择、读写及契约关系用于解释系统。职责分解与当前代码位置分别呈现，使人类同时看到业务责任和它在遗留实现中的分布。

### 从证据生成图

从一条已追踪的相关行为起步，连接真实入口、实现选择、权威写入和最终消费者，再检查会改变解释的旁路、后台写入及版本分支。任务视图标注覆盖范围；全局概貌同时标出已恢复的模块和仍待展开的区域。用“已检查这些入口及读写路径”表达调查覆盖，额外的全局唯一性判断需要相应的部署、注册和外部访问依据。

节点使用稳定的业务或模块名称，并链接实际相对路径、符号、配置或运行对象。关键边标注动作与条件，例如“提交后发布”“开关 A 选择”“读取版本 v”，将调用、数据、控制、所有权或保证依赖区分清楚。边较多时用短编号连接图旁证据说明，源码细节按需下钻。时序图中并发关系依据实际同步和交接表达，允许多种先后顺序的部分保留分支或并行表达。

每幅图注明范围、代码版本及相关环境；部署事实使用实际制品或运行版本。按关键关系标注依据：**源码可达、配置选中、运行观测、条件推断、目标设计**。混合依据用文字或图例区分；颜色作为辅助。当前结构和候选改法分别绘制或明确分区，链接各自依据。源码支持可能路径，运行记录支持对应实例，两者共同解释现状。

展开图时先说明需要判断的关系，例如“哪个入口选中实现”“谁在提交后消费状态”，再选择相关节点、边类型和上下游范围。沿图找到下一段应读源码，取得证据后修订关键边；源码承接精确条件，图承接跨位置关系。这个操作借鉴 [SeeRepo / LLM Agents Can See Code Repositories](https://arxiv.org/abs/2606.14061)（2026-06 首发、ASE 2026，§5–7）：其任务中心子图结合文本阅读主要改善部分模型的探索效率，准确率随模型和使用阶段变化。论文评估对象是 Agent 的静态结构导航；本节的人类决策视图继续以真实配置、契约和运行依据为准。

### 让人类据图作决定

围绕当前决定提供一条可读路径：“当前怎样运行 → 哪个条件产生偏差或限制 → 候选改法改变哪条关系 → 哪些行为和迁移阶段受影响”。在图旁给出推荐位置及理由、实际需要权衡的方案和会改变选择的证据缺口。已有授权内的实现选择继续自主完成；需要用户决定的产品、架构或兼容取舍明确指出具体选项及后果。

交付前沿图走读一次：从入口到最终效果解释同一业务对象，核对跨图身份与边界的一致性，沿关键边追到依据，将配置与版本分支对应到当前环境。反向从拟修改的保证追到依赖者，核对图对所声称影响范围的支持。渲染核对用于确认标签和方向可读，语义走读用于确认解释。重要推断和待展开区域保持可见，读者据此判断现状模型的覆盖。

## 定点回写与依赖传播

先定位本次改变的是设计要求、实际实现、运行条件还是推断。预期契约由批准设计及后续决策承接；代码与配置说明当前版本可能执行的路径；日志、数据与观测说明指定环境实际发生的事；架构解释从这些依据推导。四者发生冲突时，写明各自条件与后果，再决定改实现、改部署条件、修订设计或继续取证。

更新负责该判断的正文，再沿真实受影响的依赖更新引用、图和接续入口。接口变化反查调用者和外部消费者；数据变化双向检查写入、迁移、读取与旧版本；执行时序变化检查队列、确认、重试、取消和资源释放；部署选择变化核对运行版本与配置。阶段进度原位替换，详细过程由任务和 Git 历史承接。

架构判断还依赖实现之外的成立条件。为影响后续选择的重要判断保存“选择理由 → 成立条件与证据 → 依赖的行为 → 触发重看的变化”，嵌入对应架构或模块正文。增加写入者、消费者、服务实例、重试入口或旧数据类型时，检索依赖相关前提的判断，即使原代码保持原样也沿该关系回读。

新反馈与架构预测分化时，先定位变化的是运行条件、实现路径、测量解释还是原推断，再修订对应关系及依赖它的判断。局部事实按其适用范围保存；确认共同前提改变后，再向相关链路传播。源码位置索引帮助找到证据，成立条件帮助决定何时需要重新理解。

## 高保真修订与回读

整理长期架构知识时，以本次编辑开始时的文件和源码版本为基线，检查已有 Git diff 与同期改动。对拟合并或删除的每项判断，记录原位置、其依据与适用条件、保留位置及恢复路径；已有 ADR、设计文档和任务记录可承接独立设计理由。必要的旧正文由 Git 版本定位，仍影响当前选择的论证保持直接可读。

归并依据是**未来遇到相关变更时能否作出相同判断**：从保留的契约、状态归属、因果链和证据，重新推出原建议及其边界；再给出一种新事件，检查旧解释是否要求不同更新。需要重新发明关键前提、补充无来源假设或重新调查才能恢复的区别，继续保留。表达重复且推理责任相同的段落可以合并。

例如“超时后查询状态”有两条依据：请求仍在队列中，或结果已提交但确认丢失。它们当前都可能导致等待；自动重试、取消或进程重启后，前者需要判断任务是否开始，后者需要用业务身份复用已提交结果。保留提交点、结果查询路径和两种后继处置，才能让一句操作建议在新需求下继续有效。

修订后从 README／AGENTS 重新接管一次：由 ARCHITECTURE 和 STATE 找到当前契约、有效路径与下一动作；沿一条真实链路追到证据；用一个新消费者、旧数据或失败恢复情形检查保留知识怎样改变修改边界。图和正文对同一版本、同一责任关系给出一致解释。用户规则与批准设计的原文分别核对，规则调整依其授权，设计变化保留来源及决策。

文档值得长期保存的依据是它能改变搜索方向、复用选择、修改边界或验证方式。一次性搜索、逐条命令和重复阶段总结由当轮上下文承担；实现状态随实际事实迭代。

## 证据与变化提示

在关键判断旁写源码相对路径、符号、配置或运行事实，必要时记录提交版本。可选机械格式：

```text
Evidence: path=src/service.py symbol=handle_request at=abc1234
```

`path` 相对于源码根；`symbol` 是准确标识符或独特源码片段；`at` 是核对时的源码提交。工具只检查引用及源码变化，语义影响由 Agent 判断。

```bash
python3 scripts/arch_memory.py impact --root /path/to/repo --files src/service.py
python3 scripts/arch_memory.py check --root /path/to/repo
```

知识放在其他目录时，两条命令均加 `--memory-root /path/to/notes`。路径或符号变化触发回读；改名可能只影响引用，新增写入者可能改变整个状态解释。机械检查结果与语义正确性分别报告。

默认源码根目录中，辅助命令只扫描根层 Markdown 与 `flows/`；项目把架构知识放在嵌套目录时，用 `--memory-root` 指向该知识目录。这样引用检查聚焦由工作区维护的正文，源码、依赖及其他说明由语义追踪按需阅读。

## 交接保存当前事实

接管前明确已完成行为、仍需处理的差距、下一动作及其依据。后台进程、任务句柄、产物、分支、PR 和部署环境按实际需要链接。记录验证覆盖的真实路径及环境边界，保护隐私与凭据。新的 Agent 应能从简洁全局和 STATE 找到继续工作的方向，再按需取得详细依据。
